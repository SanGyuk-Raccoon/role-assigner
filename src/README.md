# 역할 뽑기 (Role Assigner)

파티 게임의 일반 역할과 마니또를 브라우저 안에서 배정하는 Next.js 앱입니다. Vercel과 base path `/role-assigner`를 유지하며, 역할 데이터는 API·데이터베이스·브라우저 저장소로 보내거나 저장하지 않습니다.

## 기능

- 참가자 2–20명, 참가자 이름 20 Unicode code point·UTF-8 80바이트
- 일반 역할 최대 20개, 역할 이름 30 code point·120바이트, 역할별 0–20명
- 일반 역할의 Fisher–Yates 셔플과 마니또의 Sattolo 단일 순환
- Web Crypto 난수만 사용하며 지원되지 않으면 배정을 중단하고 안내
- 기존 `전체 공개`·`개별 공개` 선택을 유지하며 두 방식 모두 브라우저 안에서만 배정
- 전체 공개는 배정 직후 모든 결과를 한 화면에 표시하고, 개별 공개는 승인한 참가자 결과를 목록에 유지하며 개별·전체 숨김 제공
- 한 결과만 담은 개인 링크, 모든 결과를 즉시 여는 전체 결과 링크, 이름으로 한 명씩 찾는 참가자 확인 링크
- 한 번 클릭하는 클립보드 복사와 선택 가능한 수동 복사 대체 동작

## 공개 흐름

1. `전체 공개` 또는 `개별 공개`를 고르고 참가자와 배정 종류를 입력합니다. 일반 역할이면 역할별 인원도 설정합니다.
2. 두 공개 방식 모두 서버 연결 없이 브라우저 메모리에서 같은 검증·배정 로직을 사용합니다.
3. 전체 공개는 모든 결과를 바로 표시합니다. 개별 공개는 결과를 접근성 트리에서도 숨기고, 확인을 승인한 참가자의 결과를 기존 목록에 표시합니다. 공개한 결과는 `다시 숨기기` 전까지 유지되며 `전체 결과 보기`는 같은 목록의 모든 행을 공개합니다.
4. 전체 공개에서는 모든 결과를 즉시 여는 링크를, 개별 공개에서는 참가자가 이름으로 한 명씩 확인하는 링크와 개인 링크를 복사할 수 있습니다.

개인 링크에는 해당 참가자의 표시 이름과 결과 하나만 들어갑니다. 전체 결과 링크와 참가자 확인 링크에는 전체 배정 결과가 들어갑니다. 전체 결과 링크는 열자마자 모든 결과를 표시하고, 참가자 확인 링크는 입력한 이름을 정규화해 정확히 일치하는 한 결과만 표시합니다. 참가자 목록이나 자동 완성은 제공하지 않습니다.

## 링크의 신뢰 모델

결과 JSON은 UTF-8, 패딩 없는 base64url 순서로 인코딩되어 현재 경로의 `#result=<payload>` fragment에 들어갑니다. 인코딩은 암호화·인증·접근 통제가 아닙니다.

- 링크를 가진 사람은 그 링크에 담긴 결과를 볼 수 있습니다.
- 전체 결과 링크와 참가자 확인 링크는 모두 전체 결과를 포함하므로 서로 신뢰하는 모임에서만 사용해야 합니다. 이름 입력은 인증이나 접근 통제가 아닙니다.
- 링크는 주소 표시줄, 방문 기록, 클립보드와 공유 대상에 남을 수 있습니다.
- 이미 보낸 링크는 만료·회수·원격 삭제할 수 없고 다시 배정해도 바뀌지 않습니다.
- 배정자의 전체 결과는 메모리에만 있어 새로고침하거나 페이지를 떠나면 복구되지 않습니다.

payload는 8,192자로 제한하고, 링크 진입 시 문자 집합·UTF-8·JSON·버전·정확한 필드·인원·문자열 길이·중복 이름을 다시 검사합니다. fragment와 디코딩한 결과를 서버나 로그로 전송하지 않습니다.

## 개발과 검증

```sh
npm install
npm run dev
```

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`npm test`는 정규화, 입력 상한, 역할 수, 결정적 셔플, 마니또 불변식과 링크 codec의 정상·오류 계약을 검증합니다. `npm run test:e2e`는 `/role-assigner`에서 전체 공개의 즉시 표시, 개별 공개의 목록 내 누적 공개·숨김 DOM, dialog 초점, 개인·전체 결과·참가자 확인 링크 복사와 수동 복구 동작, 네트워크 무전송, 320px 레이아웃과 자동 접근성 검사를 실행합니다.
